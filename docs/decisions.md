# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-09-23 | Standalone app for the group (IT, PL, FR, ES, DE, CH); imports Geoportale `.axpo` files but does not depend on the Geoportale, AGOL login or the Italian cadastre | Other countries have no GIS portal; Poland uses HelioScope, Spain evaluated RatedPower |
| 2026-09-23 | Only the internal toolkit (Design ESQ) — structures, stations, fences, rules — through a versioned catalog | Requested by the user; keeps designs consistent with company standards |
| 2026-09-23 | Modules are user-managed: typed in or imported from supplier roadmaps, plus a list of modules planned for the project | Requested by the user |
| 2026-09-23 | Pitch, module power (module choice) and structure type (`nVm` / `nHm`) are set by hand for each field; the tool only suggests toolkit minimums and warns | Requested by the user |
| 2026-09-23 | Scope: ground-mounted fixed and agrivoltaics. Floating, rooftop, car-park canopies and greenhouses stay out | Requested by the user |
| 2026-09-23 | English user interface, all strings in `app/js/i18n.js` | Group-wide tool |
| 2026-09-23 | Terrain: Esri World Elevation first, then single DTM / DSM upload; slopes in % | Requested by the user; ArcGIS is available in IT, PL, ES, FR, DE |
| 2026-09-23 | Electrical design left open (~6 months) | The user is gathering requirements |
| 2026-09-23 | Yield: typed-in specific yield until the internal yield tool exposes its API | API not available yet |
| 2026-09-23 | Parametric: the project stores inputs and parameters, the layout is regenerated; manual edits will be kept as exceptions | Agreed with the user |
| 2026-09-23 | Separate project, several files, no shared library with the Geoportale for now (useful parts copied once) | The Geoportale stays a single file; two apps with different users should not be released together. Revisit if copies diverge |
| 2026-09-23 | ArcGIS Maps SDK 4.34 through `$arcgis.import()`, geometry operators instead of `geometryEngine` | Same loading mechanism as 5.x (verified working in 4.34): a later migration stays small |
| 2026-09-23 | Layout computed in a local Transverse Mercator frame (scale 1) centred on the site | True metres; verified 5 000.000 m² for 100 × 50 m. Web Mercator is 0.15–0.17 % off at 45° |
| 2026-09-23 | Setbacks and exclusion buffers use round joins (planar buffer in the local frame) | Exactly "at least X m from the boundary" |
| 2026-09-23 | Workflow in steps on a left rail: 0 Terrain, 1 Areas, 2 Fields, 3 Infrastructure, 4 Output, 4b 3D, Electrical | Defined by the user |
| 2026-09-23 | Areas in categories (gross, net, exclusion, linear infrastructure, obstacle, access, mitigation, agricultural, reference) with per-object buffers instead of global ones | Requested by the user (exclusion / gross / net / obstacles, drag between categories); a power line and a ditch need different buffers |
| 2026-09-23 | Net area: taken as it is when given, otherwise gross − boundary setback; exclusions and obstacles are cut in both cases | Requested by the user; setbacks vary between countries and regions, so the setback is a project value |
| 2026-09-23 | Export coordinate system proposed from the site location with alerts, changeable by hand; measurements stay in the local frame | Requested by the user ("with alerts and information"); the national system only matters for exports |
| 2026-09-23 | Germany: UTM zone by Land (33 in BE, BB, MV, SN; 32 elsewhere, Bavaria included), from `regions.json` | The longitude rule would be wrong for eastern Bavaria and Saxony-Anhalt, western Brandenburg and Mecklenburg |
| 2026-09-23 | Italy: zone 32 west of 12° E, 33 east of it (34 not proposed); alert between 11° and 13° E | Salento is worked in zone 33; regions near 12° E use one zone for their whole territory |
| 2026-09-23 | Shapefiles read raw and converted by the SDK projection engine with their `.prj` (not by shpjs / proj4) | The SDK applies the default datum transformation (Monte Mario 1660, DHDN 1777, CH1903 1753, CH1903+ 1676), also for a WKT; proj4 without TOWGS84 puts a Monte Mario file 168 m off |
| 2026-09-23 | Project files `.pvpd` = zip with `project.json` (room for DTM and other files later); File System Access API with download fallback; autosave in the browser | A single file to share and archive; saves in place like a desktop program |
| 2026-09-24 | One "site-features" model (AGOL Axpo `schemas/site_features_model.json`) for the Geoportale drawings, the AGOL layer «IT - Site Features» (replaces Sites Notes) and this app; objects that carry its codes are never classified by keywords | Requested by the user: a structured, intuitive chain from drawing to archive to predesign. Sites Notes mixed what an object is with what it means for the design and had no link to the site |
| 2026-09-24 | Gross area from the site of work of a Geoportale project (an AREAS COLLECTION area), from a gross-area drawing, or from any file dropped on the Gross area card | Answer of the user: AREAS COLLECTION, `.axpo` or a KMZ are all valid sources |
| 2026-09-24 | Model 1.1.0: category «connection» (grid connection route, lines, estimated/confirmed), not cut from the site; «access» keeps the connection point. Route words win over power-line words in the keyword classification; a plain «cavidotto» stays an existing line | Requested by the user: the connection route was always missing; it is not a linear infrastructure (those are existing lines interfering with the site). The Geoportale can compute it on roads |
| 2026-09-24 | Keyword classification: a match whose category does not take the geometry lets the next match through | With «connection» (lines only) before «access», a point «Punto di connessione» in a KML folder «Percorso di connessione» would otherwise have ended up as a reference |
| 2026-09-24 | Grid connection routes shown with their geodesic length (per route and in total, by type), dashed until confirmed | The route length drives the cable cost of the predesign; an estimated route should look uncertain on the map |
| 2026-09-25 | Toolkit archive by country in `docs/toolkit/` (with sources and status); catalog values of a country never borrowed by another | Requested by the user: the information is scattered in the company and will keep arriving; a French rule applied in Poland would look like a toolkit value |
| 2026-09-25 | Group standards: module TOPCon 2382 × 1134 bifacial only; ground-mounted 3V9 (27 modules) at 15°; tracker 1V28 ±55°; tracker pitch agreed with the farm (no default) | Stated by the user |
| 2026-09-25 | Module power by semester from the group roadmap, column «CS - PPA FR et EU»; power of the current semester unless the project picks one; warning when the powers are more than six months old; prices not read | Stated by the user: the roadmap is updated every six months |
| 2026-09-25 | Modules used by a project are saved in its file and adopted by the library that opens it | Audit: a project opened on another computer silently took another module |
| 2026-09-25 | Italian shading angle 29° (sections «T 15° / AO 29°» of the IT toolkit), France 35° | IT toolkit DWG; the pitches of the drawing (6.85 / 10.30 m) match the formula |
| 2026-09-25 | Tracker length = modules + 1.19 m drive gap; 0.50 m between trackers in line; at most 4 in line, then 4 m | Measured on the 1V27 blocks of the IT DWG (32.33 m); dimension «4 TRACKER MAX.» |
| 2026-09-25 | Half tables (half strings) only as an option; a half keeps the column grid; 1V14 for the 1V28; the 3V9 is never split | Stated by the user |
| 2026-09-25 | Perimeter road: a template proposed for plants up to about 9 MWp, the designer decides | Stated by the user |
| 2026-09-25 | Design principle: a predesign more accurate than usual but fast and intuitive — toolkit values as defaults and suggestions, advanced options optional, choices of the designer never locked | Stated by the user: most users want a quick predesign |
| 2026-09-25 | Fence along the outline of the usable land (base minus the objects of 1 · Areas, holes not fenced); fence → structures band cut (IT 4 m, 6 m with the perimeter road); custom value allowed | IT toolkit clearances; the designer decides |
| 2026-09-25 | Stations: country sizes, 3 m kept free all around (the toolkit asks 3 m behind and beside and 1 m to the road: simplified, to verify); delivery + user stations placed at the access in one click; transformer stations by hand with a ~1 per 3 MWp hint | IT toolkit; transformer stations belong to the electrical design |
| 2026-09-25 | Internal roads = the corridors across the rows of 2 · Fields | One parameter for layout and roads |
| 2026-09-28 | Lots = separate parts of the usable land, numbered north to south; one fence each by default, lots joined by the designer share one (closing across the gaps, clipped to the site and to the other lots); groups kept as points inside the lots | User: a plant in 8 lots with 2 fences (1-3 and 4-8); fences are not one per net area |
| 2026-09-28 | PDF report drawn as vectors from the local frame (no screenshot of the map); jsPDF 4.2.1 from jsDelivr; KMZ with the tables as one multi-geometry | Exact scale, readable without a basemap licence, light files |
| 2026-09-28 | Stations snap flush with a fence within 25 m and along it, can be moved and turned; roads can be drawn, reshaped and removed (heavy / light widths of the country) | User: stations could not be moved nor aligned, roads could not be edited |
| 2026-09-25 | NZIA variant of the module roadmap ignored; IT ground clearance 1.00 m and 1V28 drive gap 1.19 m confirmed | Stated by the user |
| 2026-09-25 | Terrain optional; slope limits: fixed 3V 10 % N-S and E-W, tracker 1V 15 % in every direction (IT toolkit note), fixed 2V and AgriPV fixed 15 % in every direction; structures without a rule are not cut | Stated by the user; no invented limits |
| 2026-09-25 | Terrain sampled on a grid of the local frame (5 m by default), Horn slopes, cells partly covered by the model left unknown, patches under 250 m² ignored (app setting) | True metres as for the layout; a partial mean is not the elevation of the cell centre |
| 2026-09-28 | Libraries served by the app from `app/vendor` (built from pinned npm versions, checked by CI); only the ArcGIS Maps SDK from its CDN | Company proxies often block public CDNs; the versions are fixed and auditable (`npm audit`) |
| 2026-09-28 | SheetJS dropped: Excel roadmaps read by an own .xlsx / .xlsm reader (JSZip + DOMParser); .xls must be saved as .xlsx | The npm release 0.18.5 has known flaws (prototype pollution, ReDoS) and fixed releases are only on the SheetJS CDN; the roadmaps are .xlsm |
| 2026-09-28 | Exports for Engineering (Shapefile, DXF R12, Excel bill of quantities) in the national system of 4 · Output; lengths and areas from the local frame; `.prj` from the EPSG database (ESRI WKT); DXF layers `PVP_*` until Engineering gives its names | Hand-over without redrawing; R12 opens everywhere; measures stay true metres whatever the grid scale factor |
| 2026-09-28 | Bill of quantities without piles, cables or earthworks: listed as not included | No toolkit value per structure (piles), electrical design left open, earthworks need the survey: never invented |
| 2026-09-28 | GeoPackage export written with sql.js (vendored); no file geodatabase | User: «lascia stare i gdb». A .gdb needs GDAL in WebAssembly (~30 MB) or a writer of a proprietary format; ArcGIS Pro opens a GeoPackage directly |
| 2026-09-28 | Background map: satellite imagery without labels (was hybrid), opacity slider on the map | User request: labels clutter the layout; a paler image makes the tables readable |
| 2026-09-28 | 3D view in step 4b on the same map (SceneView), editing stays in 2D; heights from the country toolkit (IT tracker axis by AgriPV category, standard by default), never borrowed; trackers follow the sun at the time of the view or are set by hand, without backtracking; each table follows the ground under its corners | User: category selectable with standard as default, sun tracking with a manual alternative, everything in one delivery. Backtracking is not in the toolkit |
| 2026-09-28 | Sun position by the NOAA calculator (checked against pvlib / NREL SPA within 0.01°); glTF written by the app (Y up, origin and national coordinates in the extras) | No new library; a renderer-friendly format that SketchUp, Blender and Twinmotion read |
| 2026-09-28 | 3D fixes after the first browser check (black screen): the scene starts with a camera on the site, frames it only once ready, uses World Elevation directly when the step 0 grid came from it (the designer's DTM only as custom ground), leaves out meshes with non-finite coordinates; the SceneView is now tested headless with software WebGL | User: black screen and an overlay exception in the SceneView; with main the camera stayed on the whole globe |
| 2026-10-02 | Steps renamed and renumbered in the order of their dependencies: 1 Site · 2 Terrain (optional) · 3 Layout · 4 Infrastructure · 5 Outputs; the rail is a stepper whose states (locked / ready / optional / done + key figure) come from the panels; a locked step opens with a gate saying why and a link, never a block; the app reopens on the last step unless locked, else on the first still to do | User tests: the Terrain panel (then step 0) was not understood; it depends on the site and on the structure of the layout. Approved by the user on the five proposals of the audit |
| 2026-10-02 | 3D is a 2D / 3D switch on the map with its controls in a floating card, not a step; the electrical placeholder leaves the rail (one line in Outputs) | A view of the same data, not a stage of the work; placeholders out of the product |
| 2026-10-02 | Drawing in 1 · Site ported from the Geoportale's *Disegna* pattern as it is: ① category chips with the defaults of the next drawings, ② tool cards (Point, Line, Area, Rectangle; disabled with the reason), armed tool stays armed, status line, *Last drawing* box, ↶ ↷ undo / redo (Ctrl+Z / Ctrl+Y, 40 steps); per-category draw buttons removed (import stays); rename by a button, not a double click | Same names, icons and gestures as the Geoportale for the same users; the pattern came out of its own user tests |
| 2026-10-02 | No native `confirm()`: removals show a toast with *Undo* (objects come back where they were), the only confirmations (new project, remove the terrain) use the app's dialog | User control (Nielsen #3), consistency |
| 2026-10-02 | Structure chosen from the toolkit presets of the technology, with a «custom notation» escape; gaps, tracks, half tables, target and grid position folded under *Advanced*; the module library after the results; the terrain's grid cell and small patches folded too | Progressive disclosure: three choices matter in the basic path |
| 2026-10-02 | Contrast tokens of the Geoportale (`--fill` = strong accent for filled buttons with white text, `--link` for accent texts; dark theme dark text on the light accent), focus ring on every control, icon buttons ≥ 24 px; no new colour | WCAG 2.2 AA (1.4.3, 2.4.7, 2.5.8) without changing the Axpo palette |
| 2026-10-02 | The catalog is edited through a workbook (`docs/toolkit/toolkit.xlsx`: Values sheet with Country / Key / Value / Unit / Source / Status / Note, one sheet per kind of record) and `scripts/make_toolkit.py` writes `app/catalog/toolkit.json`; the CI checks that both match; `--export` rebuilds the workbook from the JSON | User request: update roads, buildings, modules and rules without a coding session. The JSON stays the only file the app reads (no runtime Excel parsing, Git history of the values); DWGs are still transcribed by hand |
| 2026-10-04 | Geoportale and PV Predesign compute slopes the same way, in everything: the Geoportale's «Pendenze da DTM» tool is a port of `terrain/slope.js`, `terrain.js` and `geo/localframe.js` (same grid, Horn weights, limit object, patch filter, outlines); checked side by side | Stated by the user: one method, one result, whichever tool was used |
| 2026-10-04 | The slope limit is chosen by the designer in PV Predesign too, in the two ways of the Geoportale (one value in every direction, or north–south and east–west apart), with the toolkit rule of the structure as the default and a line that always says whether the limit in use is the toolkit's and what the toolkit says; the limit travels in the `.pvpd` (`terrain.limit`, `terrain.limitFrom` custom / geoportale) | Stated by the user: «the same possibility to choose the thresholds, but say what the toolkit has» |
| 2026-10-04 | The toolkit values live only in PV Predesign: the Geoportale takes the limits typed by the user and nothing else; the comparison with the toolkit is done here, at import and in 2 · Terrain | Stated by the user: the Geoportale stays generic |
| 2026-10-04 | A Geoportale project with slopes from its DTM: its elevation grid becomes the terrain of 2 · Terrain when it covers the site (no new download; cell and patch size aligned), its limit becomes the limit in use (as chosen by hand, compared with the toolkit), and the imported «steep slope» exclusion gives way to the live cut (removed with Undo), so that the slope is cut once; without a usable grid the exclusion stays and the terrain step has nothing until a terrain is loaded, which then replaces the exclusion the same way | One cut, one limit, visible and editable; the proposal of the Geoportale session, applied as is |
| 2026-10-08 | A Geoportale grid is adopted when it covers any part of the site (the covered share is shown, the slopes outside are said not to be checked, the site box at adoption travels with the grid), replaces an Esri grid of this app and never a GeoTIFF of the designer; the grid of the imported slope exclusion comes first | Audit `docs/audit/2026-10-08-geoportale-alignment.md`: the Geoportale samples one gross area plus 25 m, PV Predesign's site is the union of every gross and net area; a whole-site rule refused real projects |
| 2026-10-08 | The automatic drawings of the Geoportale (buffer strips, automatic net area, `sf_auto`) are not imported; its boundary setback is taken when none is set | They are derived from the objects with the rules of this app, which computes them live; imported, a strip doubled its object and the net froze |
| 2026-10-08 | The terrain image of the Geoportale ported to 2 · Terrain (hill-shaded elevations or slope classes, transparent outside the site plus its buffer, cut hatched) with the figures inside the site (mean and steepest slope, hectares and share over the limit, coverage) | User: "the Geoportale's tool is the more complete one, align PV Predesign"; same picture, same numbers in both tools |
